# 第一章：Transformer 基础

## 一、大语言模型（LLM）是什么？

大语言模型，英文叫 Large Language Model，本质上就是一个超级大的文字预测器。它做的事情很简单：你给它一段文字，它猜下一个字应该是什么。但它不是瞎猜——它是通过学习海量文本，掌握了语言的规律、知识的关联、还有逻辑的脉络，才做出有道理的预测。

市面上这些 LLM 的底层结构基本都是同一套东西：**Transformer**。

2017 年，一篇叫《Attention Is All You Need》（注意力就是你需要的一切）的论文，彻底改变了 AI 处理语言的范式。Transformer 就是这篇论文提出的。

---

## 二、Transformer 的核心创新：注意力机制

Transformer 最革命性的想法是什么？**让模型学会"盯着"文字看。**

传统模型读文字是一个字一个字顺着读，像人只看眼前一个字来判断上下文，后面的字还没读到就过去了。而注意力机制让模型同时看一句话里的所有字，自己学会判断哪些字对当前任务更重要。

举个例子：**"昨天我去了银行取钱"**。模型在处理"取"这个字的时候，注意力机制会让它重点"盯着""银行"——因为银行和取钱关系密切——而不会把注意力浪费在"昨天"或"我"上。

这种**聚焦相关性、忽略不相关的**，就是注意力的本质。

注意力分两种：
- **自注意力（Self-Attention）**：一个句子内部，字和字之间互相关注，搞清彼此的关系
- **交叉注意力（Cross-Attention）**：两个不同序列之间互相关注，比如翻译时原文和译文之间

---

## 三、Transformer 的三种架构

Transformer 这个地基能盖出三种不同形状的建筑：

### 1. 只看不说的"理解型"：Encoder-only（编码器架构）

代表选手：**BERT**

它只看输入，输出一个理解结果。适合做：文本分类、情感分析、实体识别。
就像一个人听别人说话，不插嘴，最后给出一个结论。

### 2. 说个不停的"生成型"：Decoder-only（解码器架构）

代表选手：**GPT、DeepSeek、Llama**

它一个一个字地吐，吐出来的字变成下一次输入的上下文，再吐下一个字。适合做：聊天、写文章、写代码。
就像一个人打开了话匣子，一直往下说。

### 3. 听懂再翻译的"转换型"：Encoder-Decoder（编码器-解码器架构）

代表选手：**T5、BART**

先理解输入（Encoder），再生成输出（Decoder）。适合做：翻译、摘要。
就像一个人先听对方说完，理解了整句话的意思，再用自己的话翻译出来。

---

## 四、预训练 + 微调：大模型的"打地基"和"装门窗"

训练一个大模型分两个阶段：

### 预训练（Pre-training）
- 用海量数据（整个互联网级别的文本），花巨资（几百万到几千万美元），训练一个通用的基础模型
- 这个过程只有大公司或顶级研究机构才做得了
- 预训练完的模型叫"基座模型"，什么都懂一点，但没有特定方向

### 微调（Fine-tuning）
- 拿一个预训练好的基座模型，用少量数据（几百到几千条就够了）训练它做特定任务
- 成本很低，普通人也能做
- 比如：用客服对话数据微调，它就变成客服专用模型；用医学文献微调，它就变成医疗助手

**关键点**：预训练给了模型"通用智商"，微调给了它"专业技能"。

这种方式叫**迁移学习（Transfer Learning）**——把从一个任务学到的知识迁移到另一个任务上。

---

## 五、大模型怎么生成文字：推理的两个阶段

大模型推理（Inference）——也就是实际生成文字的时候——分成两步：

### 第一阶段：Prefill（预填充，俗称"消化"）

你把整段输入一次性给它，它全部理解了，建立起上下文信息。这一步计算量很大（算力密集型），但只做一次。

### 第二阶段：Decode（解码，俗称"吐字"）

一个字一个字地生成输出。每吐一个字，这个字会成为下一步的上下文。这一步重复很多次（一个字一次），对内存要求很高（内存密集型），因为要记住之前吐过的所有字。

---

## 六、从输入到输出的完整流水线（Pipeline）

当你输入一段文字给大模型，后台经历了四个步骤：

```
你的文字 → Tokenizer（分词）→ Transformer（模型本体）→ Head（任务头）→ Postprocessing（后处理）→ 输出结果
```

### 1. Tokenizer：分词器
把你的自然语言文字拆成一个个最小单位（叫 token）。Token 可能是整个词、半个词，甚至一个标点符号。然后每个 token 映射成一个数字 ID，因为模型只认数字。

三种分词方式：
- **按词分（Word-based）**：每个词一个 ID，词表会非常大
- **按字分（Character-based）**：每个字符一个 ID，序列会非常长
- **子词分词（Subword）**：折中方案，常用词完整保留，生僻词切成碎片。最主流的方式。常见的 BPE、WordPiece、Unigram 都属于这类

### 2. Transformer：模型本体
拿到 token ID 后，通过几十上百层的 Transformer 结构做一堆矩阵运算，把每个 token 变成一个高维向量（embedding），然后层层传递、互相注意、提取语义。

### 3. Head：任务头
Transformer 输出一堆向量后，任务头决定最终你要什么：分类？生成下一个字？判断相关性？不同的任务接不同的"头"。

### 4. Postprocessing：后处理
把模型输出的数字转回人类可读的文字。比如 Softmax 把分数变成概率，选最可能的那个字。

---

## 七、控制生成结果的三个旋钮

大模型生成文字不是只有一个"标准答案"，你可以调整它输出的风格和创造性。有三个关键旋钮：

### Temperature（温度）
控制输出的随机性。温度低（如 0.2）→ 输出保守、稳定、一板一眼；温度高（如 0.9）→ 输出跳脱、有创意、但也可能胡说八道。

### Top-k
每步只从概率最高的 K 个候选字里选。比如 K=50，就只看前 50 个最可能的下一个字。

### Top-p（也叫 Nucleus Sampling，核心采样）
从概率最高的字开始累加，加到概率和超过 P（比如 P=0.9）为止。这个集合就是候选池。和 Top-k 不同，候选池的大小是动态的。

---

## 八、KV Cache：让吐字更快的缓存技术

推理过程中，Decode 阶段每吐一个字都要重新计算整个序列的注意力。但有个问题：前面算过的字其实不用再算一遍。

**KV Cache** 就是把之前每个字算出来的 Key 和 Value（注意力机制中的两个矩阵）存起来，吐下一个字的时候直接用缓存，不用重新算。这不影响最终结果，但速度大大加快。

代价是：占显存。

---

## 九、上下文长度：越长越贵

每多一个 token，注意力矩阵就大一圈。内存消耗随长度**平方级增长**（因为每个字都要看其他所有字），推理速度随长度**线性下降**。这决定了模型能处理的上下文不是无限长的。

动态填充（Dynamic Padding）：每次塞不同长度时，只补到本批最长那条，不统一补到固定长度，减少无意义的计算浪费。

---

## 十、BERT 的特殊 Token

BERT 这么经典的 Encoder 模型，有几个特殊符号要知道：
- **[CLS]**：放在句子开头，整个句子的"汇总表示"，分类任务就靠它
- **[SEP]**：分隔两个句子，告诉模型"这是第一句，那是第二句"
- **[MASK]**：把某个字遮住让 BERT 猜，这是 BERT 预训练的核心玩法
- **token_type_ids**：标记这个 token 属于第一句（0）还是第二句（1），用于句子对任务

---

## 十一、模型偏见与幻觉

### 偏见（Bias）
训练数据里有什么偏见，模型就学什么偏见。比如招聘数据里如果工程师大多是男的，模型就会认为工程师≈男性。**微调改不了底层的偏见**，因为那是预训练数据带来的。

使用 AI 时心里要有这根弦：模型不是中立客观的，它反映了训练数据的分布。

### 幻觉（Hallucination）
模型会**自信地编造不存在的事实**。你问它一个东西，它说得头头是道，全是假的。这不是 bug，是大模型生成机制的自然副产品——它本质是猜下一个字，不是查数据库。

所以：**大模型给你的信息，重要的必须验证。**

## 十二、要点速记

| 概念 | 一句话 |
|------|--------|
| Transformer | 靠注意力机制处理序列的神经网络架构（2017） |
| 注意力机制 | 让模型学会"盯着"相关的字 |
| Encoder-only | BERT，理解文本 |
| Decoder-only | GPT/DeepSeek，生成文字 |
| Encoder-Decoder | T5/BART，翻译和摘要 |

| Decode | 一个字一个字吐，内存密集型 |
| Pipeline | Tokenizer → Transformer → Head → Postprocessing |
| Temperature | 控制随机性，低稳高野 |
| Top-k | 只看前 K 个候选字 |
| Top-p | 候选集概率累加到 P 为止 |
